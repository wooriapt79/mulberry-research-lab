## 📌 설계 원칙

> "맵은 시각화 도구일 뿐이다. 무엇을 측정할지가 먼저다."

- 식품사막화 지수(FDI)를 먼저 확정한 뒤 KOSIS Open API 기반 맵을 구축한다.
- FDI는 공공 통계 데이터(KOSIS)와 Mulberry 현장 데이터(Luna Local Provider DB)를 결합한 **하이브리드 지수**다.
- **방향성 원칙 (필수 고정):** FDI 값이 클수록 식품사막화 위험이 높음. 모든 구현에서 이 방향을 통일한다.

## 2. 수학적 공식 (Copilot 정교화)

### 2-1. 지표 표준화

**Z-score 표준화** (비교 연구용):
```
x*ᵢ = (xᵢ - μᵢ) / σᵢ
```

**Min-Max 정규화** (정책 등급화용, 권장):
```
x*ᵢ = (xᵢ - min(xᵢ)) / (max(xᵢ) - min(xᵢ))
```
→ 초기 구현은 **Min-Max** 사용. 데이터 축적 후 Z-score 전환 검토.

---

### 2-2. 영역별 지수

**접근성 지수 (A) — 비선형 감쇠 함수 적용**
```
A = Σⱼ qⱼ · e^(-λ · tᵢⱼ)
```
- `qⱼ`: 점포 j의 건강식품 가중치 (신선식품 취급 시 +1, 편의점만 있으면 +0.3)
- `tᵢⱼ`: 지역 i에서 점포 j까지의 이동시간 (분)
- `λ`: 거리 감쇠 계수 (초기값: **λ = 0.05** / 30분 이동 시 약 22% 감쇠)
- **해석:** A 값이 작을수록 접근성 나쁨 → FDI 기여 시 역수 처리

```
A_normalized = 1 - Min-Max(A)   # A가 작을수록 위험 높음
```

---

**경제성 지수 (E)**
```
E = β₁·P* + β₂·F* + β₃·L*
```
- P*, F*, L* 모두 높을수록 위험 → 합산 후 FDI에 양(+)으로 기여
- 초기 가중치 (균등): β₁ = β₂ = β₃ = 1/3

---

**이용가능성 지수 (U) — 위험 방향 명확화 [v0.2 수정]**

> ⚠️ **v0.1 오류:** 원래 공식 `U = γ₁·H* - γ₂·C* + γ₃·(H*·(-C*))` 은
> H*가 높고(좋은 상황) C*가 낮을 때 U가 음수가 되어 FDI에 역방향으로 기여하는 문제 발생.
> v0.2에서 위험 방향으로 재해석.

```
U_risk = γH·(1 - H*) + γC·C* + γint·(1 - H*)·C*
```
- `(1 - H*)`: 건강식품이 **부족할수록** 위험 증가
- `C*`: 편의점 비율이 높을수록 위험 증가
- `γint` 항 (상호작용): 건강식품 부재 + 편의점 집중이 겹칠 때 위험 **증폭**
- 가중치: γH = 0.4, γC = 0.4, γint = 0.2
- **결과:** U_risk ∈ [0, 1], 클수록 위험 → FDI에 양(+)으로 기여

---

**취약성 지수 (V)**
```
V = δ₁·O* + δ₂·Dv* + δ₃·Y* + δ₄·N*
```
- 모든 지표 높을수록 위험 → FDI에 양(+)으로 기여
- 초기 가중치 (균등): δ₁ = δ₂ = δ₃ = δ₄ = 1/4

---

**공급 검증 지수 (S) — Mulberry 특화**
```
S = μ₁·(1 - Mulberry_등록비율) + μ₂·(1 - Passport_검증비율) + μ₃·(1 - 예약가능비율)
```
- 등록·검증·예약 가능한 업체가 많을수록 S 감소 (위험 낮음)
- 초기 가중치 (균등): μ₁ = μ₂ = μ₃ = 1/3

---

### 2-3. 최종 FDI 공식

```
FDI_M = wA·A_norm + wE·E + wU·U + wV·V + wS·S
```

| 영역 | 변수 | 초기 가중치 | 비고 |
|------|------|------------|------|
| 접근성 | wA | 0.25 | 비선형 감쇠 함수 적용 |
| 경제성 | wE | 0.20 | 물가·소득 데이터 |
| 이용가능성 | wU | 0.20 | 상호작용 항 포함 |
| 취약성 | wV | 0.25 | 고령·장애·유소년 |
| 공급검증 | wS | 0.10 | Mulberry 현장 데이터 |
| **합계** | | **1.00** | |

> ⚠️ **방향성 고정:** FDI_M 값이 클수록 식품사막화 위험 높음.  
> 모든 개발·시각화에서 이 방향을 반드시 준수한다.

## 3. 정책 등급화 [v0.2 수정 — 방향 오류 정정]

## 7. 해외 유사 지수 비교 분석

### 7-1. USDA Food Access Research Atlas (미국)

| 항목 | 내용 |
|------|------|
| 운영 | 미국 농무부(USDA) Economic Research Service |
| 측정 단위 | 센서스 트랙 (Census Tract) |
| 핵심 차원 | (1) 거리·점포 수, (2) 소득·차량 보유, (3) 지역소득·대중교통 |
| 식품사막 정의 | 저소득 + 슈퍼마켓 1마일(도심)/10마일(농촌) 이상 거리 |
| 기술 | 직선거리 기반 (GIS 버퍼 분석) |
| 한계 | 이동시간 미반영, 비선형 감쇠 없음 |

**Mulberry FDI_M 대비:** USDA는 이진(binary) 분류 (사막/비사막). 우리는 0~1 연속 점수 + 비선형 감쇠함수로 더 세밀한 등급화 가능.

### 7-2. UK E-Food Desert Index (EFDI)

| 항목 | 내용 |
|------|------|
| 운영 | Consumer Data Research Centre / University of Leeds |
| 측정 단위 | Lower Super Output Area (약 1,500 가구) |
| 4대 드라이버 | ① 식료품 소매 근접성·밀도, ② 교통 접근성, ③ 사회경제·인구통계, ④ e-Commerce 가용성 |
| 핵심 기술 | **Spatial Interaction Model (SIM)**: 점포까지의 흐름(flow)을 중력 모델로 모델링 |
| 특징 | 온라인 장보기 포함 (E-Food Desert → e-Commerce 반영) |

**SIM 공식 (참고):**
```
Tᵢⱼ = Aᵢ · Oᵢ · Wⱼᵝ · exp(-λ · cᵢⱼ)
```
- Wⱼ: 점포 j의 규모(매장 면적, 품목 수)
- cᵢⱼ: 이동비용
- β, λ: 보정 파라미터

**Mulberry FDI_M 대비:** EFDI의 SIM은 우리 감쇠함수와 설계 철학이 유사. 향후 λ 캘리브레이션 시 EFDI 방법론 참고 예정. 단, 한국은 e-Commerce(쿠팡·마켓컬리) 비중이 높아 S 영역에 온라인 주문 가능성을 추가 검토 필요.

### 7-3. Global Food Security Index (GFSI)

| 항목 | 내용 |
|------|------|
| 운영 | Economist Impact (구 EIU) |
| 범위 | 113개국 국가 단위 |
| 3대 영역 | 구매력(Affordability) + 가용성(Availability) + 품질·안전(Quality & Safety) |
| 지표 수 | 28개 |
| 2022 상위권 | 핀란드 83.7, 아일랜드 81.7, 일본 79.5, 캐나다 79.1 |
| 한국 | 약 76점대 (상위권) |

**Mulberry FDI_M 대비:** GFSI는 국가 단위 거시 지수. 우리 FDI_M은 시군구(읍면동) 단위 미시 지수. GFSI의 경제성(E) + 가용성(U) 구조가 우리 E·U 영역과 직접 대응.

### 7-4. FAO FIES (Food Insecurity Experience Scale)

| 항목 | 내용 |
|------|------|
| 운영 | FAO (유엔 식량농업기구) |
| 측정 방법 | 가구 단위 8문항 설문 (경험 기반) |
| 특징 | "음식을 걱정한 적 있나?", "하루를 굶은 적 있나?" 등 직접 경험 측정 |
| 용도 | 국제 비교, SDG 2 (기아 종식) 모니터링 |

**Mulberry FDI_M 대비:** FIES는 공급 측(supply-side)이 아닌 수요 측(demand-side) 측정. 우리 공식은 공급 측 중심이므로, 향후 Luna 사용자 대화 데이터(체감 식품 접근성)를 FIES 대용 지표로 활용 검토 가능.

## 8. 보안 및 개인정보 원칙

1. 개인 식별 정보(이름·주소·연락처)는 FDI 계산에 사용하지 않는다.
2. 모든 지표는 **시군구 단위 집계값**만 사용한다 (개인 단위 데이터 처리 금지).
3. Mulberry Local Provider DB에서 가져오는 데이터는 AP2 계약 완료 업체만 포함한다.
4. Luna Search API 결과 중 개인정보가 포함된 항목은 HumanReviewGate 처리 후 집계한다.
