# ShopMate 개발 명세서 (Development Specification)

## 1. 기획 의도 및 배경

### 1.1 문제 정의
- **정보 비대칭**: 소비자는 판매자가 제시하는 가격과 정보를 수동적으로 받아들일 수밖에 없음.
- **알고리즘 편향**: 기존 플랫폼은 판매자 중심의 수익 모델을 기반으로 하여, 소비자에게 최적이 아닌 상품을 추천함.
- **데이터 주권 부재**: 개인의 쇼핑 이력과 취향 데이터가 플랫폼에 귀속되어 개인이 활용하지 못함.
- **검증 없는 정보**: 외부 쇼핑몰의 가격 정보를 검증 없이 수용하여, 실제 가치와 괴리된 구매 결정 발생.

### 1.2 해결 방안: ShopMate
ShopMate 는 외부 데이터에 종속되지 않는 **자체 검증 파이프라인**을 구축합니다.
1. **수집 (Hunter)**: 다수의 소스에서 데이터를 수집합니다.
2. **검증 (Validator)**: 통계적 분석과 히스토리 비교를 통해 '공정 가격'을 산출하고 이상치를 제거합니다.
3. **저장 (Librarian)**: 검증된 데이터만을 자체 DB 에 축적하여 지식으로 활용합니다.

이를 통해 **"외부 플랫폼의 가격 정책"이 아닌 "우리가 검증한 가치"**를 기준으로 사용자를 안내합니다.

## 2. 시스템 아키텍처 및 에이전트 구성

ShopMate 는 총 5 개의 특화 에이전트 (Node) 로 구성되며, 각 노드는 명확한 책임 영역을 가집니다.

### 2.1 에이전트 상세 역할

| # | 에이전트명 | 역할 설명 | 주요 기능 | 위치 |
|:-:|:-:|:-:|:-:|:-:|
| 1 | **Concierge** | 사용자 인터페이스 및 의도 파악 | - 자연어 대화 처리<br>- 사용자 프로파일링 (취향, 예산)<br>- 프라이버시 필터링 (민감 정보 제거) | Edge (Raspberry Pi) |
| 2 | **Hunter** | 데이터 수집 (Data Collection) | - 오픈마켓 API 연동<br>- 웹 크롤링 (가격, 리뷰, 스펙)<br>- 실시간 할인 정보 모니터링 | Cloud (Railway) |
| 3 | **Validator** | 데이터 검증 (Verification) | - **핵심 모듈**: 가격 신뢰도 분석<br>- 다수 소스 간 가격 비교 (Cross-validation)<br>- 이상치 ( outlier) 탐지 및 제거<br>- '공정 가격' 산출 알고리즘 실행 | Cloud/Edge Hybrid |
| 4 | **Advisor** | 추천 전략 수립 | - 사용자 맥락과 검증된 데이터 매칭<br>- 대안 상품 제시 (Cost-performance 분석)<br>- 구매 시기 권고 (가격 변동 예측) | Cloud |
| 5 | **Librarian** | 지식 관리 (Knowledge Base) | - 자체 DB(PostgreSQL+Vector) 구축<br>- 학습용 데이터 정제 및 저장<br>- 쇼핑 히스토리 및 가격 추이 관리 | Database Layer |

### 2.2 데이터 흐름 (Data Flow)
1. **User Input**: 사용자가 Concierge 에게 "노트북 추천해줘" 요청.
2. **Intent Parsing**: Concierge 가 의도를 파악하고 Hunter 에게 검색 지시.
3. **Data Gathering**: Hunter 가 외부 소스에서 원천 데이터 수집.
4. **Verification**: Validator 가 수집된 데이터의 신뢰성을 검증하고 '공정 가격' 계산.
5. **Storage**: Librarian 이 검증된 데이터를 DB 에 저장 (히스토리 누적).
6. **Recommendation**: Advisor 가 DB 와 사용자 프로필을 기반으로 최적의 안 생성.
7. **Response**: Concierge 가 사용자에게 투명한 근거와 함께 결과 전달.

## 3. 모듈 연동 계획

### 3.1 내부 모듈 연동 (Mulberry Ecosystem)
- **공동구매 엔진 (Group Buy Module)**:
    - Advisor 가 '공정 가격' 대비 할인율이 높은 상품을 발견하면, 공동구매 모듈에 자동으로 안건을 등록.
    - 연구소 회원들의 구매 희망량을 집계하여 추가 할인을 유도하는 워크플로우 연동.
- **자율 경제 지갑 (Wallet)**:
    - 구매 완료 시 포인트 적립, 현금성 자산 연동.
    - Jr. Agent 의 활동 보상 (토큰) 지급 시스템과 연결.

### 3.2 외부 모듈 연동
- **오픈마켓 API**: 쿠팡, 네이버쇼핑, 11 번가 등 주요 플랫폼의 상품/가격 API 연동.
- **결제 게이트웨이**: PG 사 연동을 통한 안전한 결제 처리.
- **물류 추적**: 배송 상태 실시간 모니터링.

## 4. 데이터베이스 설계 (자체 DB 구축)

외부 의존성을 줄이기 위해 **자체 DB**를 핵심 자산으로 구축합니다.

### 4.1 DB 구성
- **PostgreSQL (관계형)**:
    - `Users`: 사용자 프로필, 선호도, 예산 설정.
    - `Products`: 상품 기본 정보 (스펙, 카테고리).
    - `PriceHistory`: 시간별 가격 추이 (검증된 데이터만 저장).
    - `Orders`: 구매 이력, 공동구매 참여 내역.
- **Qdrant (벡터 DB)**:
    - 상품 리뷰 임베딩, 사용자 취향 벡터 저장.
    - 의미 기반 유사 상품 추천에 활용.
- **Redis (캐싱)**:
    - 실시간 가격 정보, 세션 데이터 임시 저장.

### 4.2 데이터 검증 로직 (Validator Agent)
- **신뢰도 스코어**: 같은 상품의 가격이 여러 소스에서 얼마나 일치하는지 점수화.
- **이상치 제거**: 평균 가격 대비 ±20% 벗어나는 데이터는 '노이즈'로 간주하고 제외.
- **시간 가중치**: 최근 데이터에 더 높은 가중치를 부여하여 현재 시점의 '실세가' 반영.

## 5. 사용자 경험 (UX) 전략

### 5.1 편의성 중심 설계
- **Chat-First Interface**: 복잡한 검색 필터 대신 "50 만 원 이하로 배터리 좋은 노트북 찾아줘" 같은 자연어 입력 지원.
- **투명성 제공**: "이 상품을 추천한 이유: 1. 동급 대비 가격 15% 저렴, 2. 최근 리뷰 평점 4.8, 3. A/S 만족도 높음"과 같이 근거 명시.
- **사전 알림**: 관심商品の 가격이 목표가에 도달하면 푸시 알림 전송.

### 5.2 프라이버시 보호 (Edge AI)
- 민감한 사용자 정보 (주소, 결제 정보, 대화 내용 중 비공개 부분) 는 라즈베리 파이 (Edge) 에서 처리하여 클라우드로 전송되지 않도록 필터링.
- Concierge Agent 가 로컬에서 1 차 가공 후, 필요한 검색 키워드만 클라우드로 전달.

## 8. 기대 효과 및 수익 모델

### 8.1 기대 효과
- **사용자**: 합리적인 가격에 최적의 상품 구매, 시간 절약, 데이터 주권 확보.
- **연구소**: 자체 쇼핑 데이터베이스 확보, 공동구매를 통한 경제적 수익 창출, Jr. Agent 실전 교육장 제공.

### 8.2 수익 모델
1. **제휴 마케팅**: 공정한 추천을 기반으로 한 구매 전환 수수료.
2. **공동구매 마진**: 대량 구매를 통한 추가 할인분의 일부 수익화.
3. **프리미엄 구독**: 고급 분석 리포트, 우선 추천, 자동 구매 기능 제공.
4. **B2B 데이터 판매**: 검증된 쇼핑 트렌드 데이터 및 가격 변동 분석 리포트.
